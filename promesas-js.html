¿Cómo funciona una promesa en JS?

Septiembre 2026

Tabla de contenido Introducción ¿Qué es una promesa? Then y catch

Esta duda me la planteé armando la parte de fetch de un proyecto: pedía datos a una API y no entendía por qué mi código intentaba usarlos antes de que llegaran. Investigando, encontré que la respuesta está en cómo funcionan las promesas en JavaScript.

¿Qué es una promesa?

Imagina que pides comida a domicilio. Te dan un número de pedido al instante, pero la comida no llega en ese momento — llega después. Ese número de pedido es, más o menos, lo que es una promesa: un objeto que representa un valor que todavía no existe, pero que existirá (o fallará) en el futuro.

Una promesa siempre está en uno de estos 3 estados:

  • pending (pendiente): todavía no se sabe el resultado
  • fulfilled (cumplida): todo salió bien
  • rejected (rechazada): algo falló
const promesa = new Promise((resolve, reject) => {
  const exito = true;

  if (exito) {
    resolve('¡Listo!');
  } else {
    reject('Algo salió mal');
  }
});

Then y catch

Una vez que tienes una promesa, usas .then() para decir "cuando esto se resuelva bien, haz esto", y .catch() para "si algo falla, haz esto otro":

promesa
  .then((resultado) => {
    console.log(resultado); // "¡Listo!"
  })
  .catch((error) => {
    console.error(error);
  });

Así se ve aplicado a una petición real con fetch, que es justo la duda que me hizo escribir este post:

fetch('https://api.ejemplo.com/datos')
  .then((respuesta) => respuesta.json())
  .then((datos) => {
    console.log(datos);
  })
  .catch((error) => {
    console.error('Hubo un error:', error);
  });

La primera vez que vi esto no entendía por qué había dos .then() seguidos — ahora sé que el primero convierte la respuesta cruda en JSON (que también toma tiempo, por eso es otra promesa), y el segundo ya trabaja con los datos listos.
